# 版本升级

从经过审查的固定提交发布，每次升级先在独立测试环境完成类型检查、测试和构建，
再验证相关账号、命令和文件流程。

## 保持实例连续性

升级应用代码时沿用：

- 固定 `BRIDGE_ISSUER`、MCP 地址、OAuth subject 与账户别名。
- 签名 JWKS/kid、状态加密密钥、密码哈希、Cron secret 与应用 secret。
- 飞书 app/user 绑定及 scopes、Upstash 连接、namespace、Blob store。
- 最新持久状态：用户令牌、OAuth grant、上传清单和写入回执。

格式标识和密钥派生上下文属于持久协议，版本更新时保持稳定；涉及格式变化的版本，
按对应说明准备备份和恢复方案。协议回归使用合成数据验证。

## 发布与回退

1. 记录当前生产部署及待发布提交，按顺序发布。
2. 在独立测试环境验证改动，使用明确的生产配置构建和发布。
3. 用已有客户端验证连接，以及本次涉及的读取、文件、授权或维护流程。
4. 观察 HTTP 状态、stateOps、续期提示和服务商用量。遇到存储故障，检查连接配置、
   服务状态和配额，保留现场授权状态。
5. 需要回退时，恢复已验证的应用版本并继续使用最新持久状态，接续已经轮换的令牌。
   涉及持久格式变化时同时执行该版本的恢复步骤。

日常观察见 [运维与用量](operations.md)。
